# 研究方法论

## 一、多轮搜索策略

### 第一轮：广度搜索（3-5 次搜索）

**目标**：了解主题全貌，建立知识框架。

| 搜索目标 | 搜索策略 | 预期产出 |
|---------|---------|---------|
| 主题背景 | 主题名 + overview/introduction/概述 | 基本概念、发展历程 |
| 当前现状 | 主题名 + 2025/2026 + current state/现状 | 最新进展、关键数据 |
| 争议焦点 | 主题名 + debate/controversy/争议 | 不同观点、分歧所在 |
| 关键人物 | 主题名 + expert/leader/thought leader | 权威声音、可引用观点 |
| 相关事件 | 主题名 + latest news/recent development | 时效性素材 |

### 第二轮：深度搜索（每个核心论点 1-2 次搜索）

**目标**：为每个论点找到有力证据。

| 搜索目标 | 搜索策略 | 预期产出 |
|---------|---------|---------|
| 权威数据 | 论点关键词 + statistics/data/report/研究报告 | 可引用的数据点 |
| 案例证据 | 论点关键词 + case study/example/案例 | 具体案例故事 |
| 专家观点 | 论点关键词 + expert opinion/interview/专家 | 权威引述 |
| 最新研究 | 论点关键词 + research/study/paper/论文 | 学术支撑 |

### 搜索关键词构造技巧

- **中英文分别搜索**：同一个主题，中文搜索侧重国内视角，英文搜索侧重国际视角
- **同义词扩展**：如搜索"远程办公"，同时搜索"居家办公""在家工作""remote work""WFH"
- **限定时间范围**：加上年份过滤，优先获取最新信息
- **加站点限定**：如 `site:mckinsey.com AI impact`、`site:arxiv.org transformer` 定向搜索权威来源
- **组合关键词**：主题 + 角度 + 限定词，如"AI education impact statistics 2025"

## 二、信息源分级体系

### Tier 1：原始研究 / 官方数据（最高可信度）

| 来源类型 | 示例 |
|---------|------|
| 学术论文 | Nature、Science、arXiv、SSRN、Google Scholar |
| 政府报告 | 国家统计局、WHO、US Bureau of Labor Statistics |
| 企业财报 | SEC filings、年报、IPO 招股书 |
| 官方数据库 | World Bank Open Data、UN Data、中国国家数据 |

**引用要求**：标注作者、年份、出处，可追溯原文

### Tier 2：权威媒体 / 行业报告（高可信度）

| 来源类型 | 示例 |
|---------|------|
| 顶级媒体 | NYT、The Economist、Financial Times、BBC |
| 咨询报告 | McKinsey、BCG、Bain、Deloitte、Gartner、IDC |
| 行业期刊 | MIT Technology Review、Harvard Business Review |
| 专业媒体 | TechCrunch、Wired、Bloomberg、经济观察报、财新 |

**引用要求**：标注媒体名、日期、文章标题

### Tier 3：行业媒体 / 专家博客（中等可信度）

| 来源类型 | 示例 |
|---------|------|
| 行业媒体 | 36氪、虎嗅、少数派、InfoQ、The Verge |
| 专家博客 | 知名行业专家的个人博客、Substack |
| 平台内容 | 知乎高赞专业回答、Medium 热门文章 |

**引用要求**：标注作者/平台、日期，并交叉验证核心数据

### Tier 4：社区讨论 / 用户生成内容（参考价值，需验证）

| 来源类型 | 示例 |
|---------|------|
| 社区讨论 | Reddit、Hacker News、V2EX、知乎问答 |
| 社交媒体 | Twitter/X、LinkedIn Posts、微博 |
| 用户评价 | 产品评论、App Store 评价、G2 Reviews |

**引用要求**：仅作为观点佐证或趋势感知，不作为事实依据。核心数据必须从 Tier 1-2 验证。

## 三、交叉验证规则

| 规则 | 说明 |
|------|------|
| **关键数据双源验证** | 文中引用的关键数据（市场规模、增长率、用户数等）必须从至少 2 个独立来源确认 |
| **单源数据标注** | 如果某个数据只找到 1 个来源，必须标注"据 [来源名] 数据"，不说"研究表明" |
| **矛盾数据处理** | 如果不同来源的数据矛盾，优先采用 Tier 更高的来源，或同时呈现两个数据并说明差异原因 |
| **时效性验证** | 数据超过 2 年的，标注"截至 [年份] 数据"；超过 5 年的原则上不使用 |
| **上下文完整** | 引用数据时必须包含上下文（"全球范围"还是"某国"、"所有行业"还是"科技行业"） |

## 四、事实核查清单

每完成研究后，逐项核查：

| 检查项 | 标准 |
|--------|------|
| 数据来源标注 | 每个数据点都能追溯到具体来源 |
| 数据时效性 | 优先使用 2 年内的数据，标注数据年份 |
| 来源可靠性 | 核心论据来自 Tier 1-2 来源 |
| 上下文完整性 | 数据的适用范围、前提条件说清楚 |
| 因果关系验证 | 不把相关性当因果性（"A和B同时发生" ≠ "A导致B"） |
| 引述准确性 | 引用的专家观点确实是该专家说的 |
| 数字一致性 | 同一个数据在文中多处出现时保持一致 |

## 五、研究笔记模板

研究过程中，将信息整理为以下结构化格式保存到 `research-notes.md`：

```markdown
# 研究笔记：[主题]

## 研究日期：[日期]

---

### 核心发现

1. [发现1] — 来源：[来源名]，置信度：高/中/低
2. [发现2] — 来源：[来源名]，置信度：高/中/低
3. ...

---

### 可用引用

| 编号 | 引用内容 | 来源 | Tier | 置信度 |
|------|---------|------|------|--------|
| R1 | [具体数据/观点] | [完整来源信息] | T1/T2/T3/T4 | 高/中/低 |
| R2 | ... | ... | ... | ... |

---

### 信息空白

- [还需要搜索的信息1]
- [还需要搜索的信息2]

---

### 矛盾信息记录

| 数据点 | 来源A说 | 来源B说 | 处理建议 |
|--------|--------|--------|---------|
| [数据] | [版本A] | [版本B] | [采用/同时呈现/需进一步确认] |
```
