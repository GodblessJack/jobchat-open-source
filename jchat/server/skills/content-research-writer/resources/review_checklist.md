# 三维度 Review 检查清单

每篇文章完成后，必须执行以下三维度 Review。Review 结果以报告形式输出，发现问题必须修改后再交付。

---

## 维度一：内容质量 Review

| 检查项 | 标准 | 判定方式 |
|--------|------|---------|
| 核心论点清晰度 | 读完后能用一句话概括文章核心观点 | 如果概括不出来，说明论点不清晰 |
| 论据充分性 | 每个核心论点至少有 1 个可追溯的信息源支撑 | 删掉论据后，论点是否变成空话 |
| 信息准确性 | 引用的数据和事实可追溯到具体来源 | 检查每个数据点是否标注了来源 |
| 深度与独特视角 | 不是信息搬运，而是有分析、有洞察 | 是否提供了读者在别处看不到的价值 |
| 信息密度 | 无水文段落——每段都有实质信息量 | 删掉任何一段后文章是否变差，如果不变差则该段是水文 |

### 内容问题修复策略

| 问题 | 修复方式 |
|------|---------|
| 论点不清晰 | 在开头或第一节用 1 句话明确点出核心观点 |
| 论据不足 | 补充具体数据、案例或专家引述 |
| 信息不准确 | 核实来源，修正或删除不可靠的数据 |
| 缺乏深度 | 增加原因分析、对比视角或延伸思考 |
| 有水文段落 | 删除或压缩为 1-2 句融入其他段落 |

---

## 维度二：写作质量 Review

| 检查项 | 标准 | 判定方式 |
|--------|------|---------|
| Hook 吸引力 | 开头能在 3 秒内抓住读者注意力 | 删掉开头前 2 句，是否损失了吸引力 |
| 结构完整性 | 大纲中规划的所有章节都已完整呈现 | 逐一对照大纲检查 |
| 段落衔接流畅度 | 段落之间有逻辑衔接，无突兀跳转 | 连续阅读时是否有"突然换了话题"的感觉 |
| 句式多样性 | 长短句交替，不是所有句子都是相同结构 | 检查连续 5 句是否结构相同 |
| 语气一致性 | 全文语气风格统一，无突然切换 | 开头的语气和结尾的语气是否一致 |
| 篇幅达标 | 字数/词数在目标范围内 | 统计正文字数（不含标题、引用列表） |

### 写作问题修复策略

| 问题 | 修复方式 |
|------|---------|
| Hook 无力 | 参考 hook_library.md 替换为更有吸引力的开头 |
| 结构缺失 | 补充缺失的章节内容 |
| 衔接生硬 | 在段落间加过渡句或调整段落顺序 |
| 句式单调 | 变换句式（长短交替、问句穿插、引用点缀） |
| 语气不一致 | 统一为开头确定的语气，修正偏差段落 |
| 篇幅偏差 | 超长则精简（删重复/次要信息），不足则补充 |

---

## 维度三：受众匹配 Review

| 检查项 | 标准 | 判定方式 |
|--------|------|---------|
| 专业深度适配 | 专业术语的使用量匹配目标受众水平 | 非专业受众能否不查资料读懂；专业受众是否觉得太浅 |
| 语言风格匹配 | 风格符合目标平台和受众习惯 | 对照 style_guide.md 中的平台预设 |
| 行动号召有效性 | 结尾的 CTA 清晰且与读者利益相关 | 读者看完是否知道"下一步该做什么" |
| 可读性评估 | 段落长度、句子复杂度适合目标阅读场景 | 移动端阅读是否需要反复滚动回看 |

### 受众问题修复策略

| 问题 | 修复方式 |
|------|---------|
| 太专业 | 增加解释性文字、用类比降低理解门槛 |
| 太浅 | 增加技术细节、行业内参、深度分析 |
| 风格不匹配 | 参照 style_guide.md 对应平台规范修正 |
| CTA 无效 | 替换为具体可执行的下一步行动 |
| 可读性差 | 拆分长段落、简化长句、增加小标题 |

---

## Review 输出格式

```
## Review 报告

### 维度一：内容质量
- 核心论点：[一句话概括]
- 论据充分性：✅达标 / ❌[X]个论点缺少支撑
- 信息准确性：✅达标 / ❌[X]个数据缺少来源
- 信息密度：✅达标 / ❌发现[X]段水文
- 判定：✅达标 / ❌需修改
- 问题（如有）：[具体问题]

### 维度二：写作质量
- Hook 吸引力：✅有效 / ❌需加强
- 结构完整性：✅完整 / ❌缺失[X]个章节
- 段落衔接：✅流畅 / ❌[X]处需优化
- 语气一致性：✅统一 / ❌[X]处偏差
- 篇幅：[实际字数] / 目标[X]字 → ✅达标 / ❌偏差
- 判定：✅达标 / ❌需修改
- 问题（如有）：[具体问题]

### 维度三：受众匹配
- 目标受众：[画像描述]
- 目标平台：[平台名]
- 专业深度：✅适配 / ❌[太深/太浅]
- 语言风格：✅匹配 / ❌需调整
- CTA 有效性：✅有效 / ❌需优化
- 判定：✅达标 / ❌需修改
- 问题（如有）：[具体问题]

### 综合判定
- ✅✅✅ 三维度全部达标，可交付
- ❌ [X]个维度需修改，已自动修正，修正后重新 Review
```

**规则**：如果任何一个维度判定为"需修改"，必须先修改再重新 Review，直到三维度全部达标才能交付。
