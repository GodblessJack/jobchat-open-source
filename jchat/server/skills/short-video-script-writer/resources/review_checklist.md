# 三维度结构化 Review 机制

每篇口播稿完成后，必须执行以下三维度 Review。Review 结果以表格形式输出，发现问题必须修改后再交付。

---

## 维度一：文案长度 Review

### 检查项

| 检查项 | 标准 | 判定方式 |
| :--- | :--- | :--- |
| 总字数 | 短版120-200字 / 标准版200-300字（目标250字） / 长版300-450字 | 统计正文字数（不含标题、编号、封面文字提示） |
| 是否超出上限 | 不得超过目标篇幅上限的10% | 超出则必须删减 |
| 是否低于下限 | 不得低于目标篇幅下限的90% | 不足则必须补充信息 |
| 口播时长估算 | 短版15-25秒 / 标准版30-40秒 / 长版40-60秒（所有篇幅严格控制1分钟内） | 按每秒约7-8个字估算 |
| 信息密度 | 每100字至少包含1个具体数据点（薪资/岗位数/日期/百分比） | 数据点数 ÷ 总字数 × 100 ≥ 1 |

### 长度问题修复策略

| 问题 | 修复方式 |
| :--- | :--- |
| 超长 | 优先删减：重复表述 → 次要福利细节 → 过渡句 → 背景铺垫。标准版目标250字，超过300字必须精简 |
| 过短 | 优先补充：缺失的薪资数据 → 留学生专属优势 → 具体福利细节 → 截止时间 |
| 信息密度不足 | 将模糊表述替换为具体数字（"薪资不错" → "年薪30万起"） |

## 维度二：文案结构 Review

### 检查项

| 检查项 | 标准 | 判定方式 |
| :--- | :--- | :--- |
| 钩子开头 | 前1-2句是否为有效钩子（利益/紧迫/共鸣/痛点/新闻/揭秘/数据） | 删掉前2句，是否损失了"抓注意力"的效果 |
| 结构完整性 | 是否包含所选模板要求的所有必要环节 | 逐一对照模板的结构骨架 |
| 留学生锚定 | 是否有至少1处明确的留学生相关性说明 | 搜索"留学生/海归/双语/国际/海外"等关键词 |
| 互动收尾 | 是否以"敲/扣【关键词】"格式收尾 | 检查最后一句 |
| 信息层次 | 信息是否按逻辑顺序排列（非随机堆砌） | 参照 logic_rules.md 中的5种排列逻辑 |
| 过渡自然 | 各环节之间是否有自然衔接 | 读出来是否有"突然跳到另一个话题"的感觉 |

### 结构完整性对照表

对照所选模板，逐一检查每个结构环节是否存在：

```
模板要求的环节：  ✅存在 / ❌缺失 / ⚠️存在但不完整
- 钩子开头：      [  ]
- 环节一（XX）：   [  ]
- 环节二（XX）：   [  ]
- 环节三（XX）：   [  ]
- ...
- 互动收尾：      [  ]
```

缺失的环节必须补上，不完整的环节必须补全。

### 结构问题修复策略

| 问题 | 修复方式 |
| :--- | :--- |
| 缺少钩子 | 从 hook_library.md 中选择匹配的钩子加到开头 |
| 缺少留学生锚定 | 在岗位/政策描述后，补充"留学生为什么适合/有优势"的1-2句 |
| 缺少互动收尾 | 补充"敲/扣【关键词】"格式的收尾句 |
| 信息堆砌无层次 | 重新按逻辑顺序排列（重要性递减/时间顺序/总分结构） |
| 过渡生硬 | 在环节之间加入1个过渡短句（如"更关键的是"、"除了薪资"、"再来看看"） |

## 维度三：文案逻辑 Review

### 检查项

| 检查项 | 标准 | 判定方式 |
| :--- | :--- | :--- |
| 核心论点清晰 | 读完后能用一句话概括"这篇稿子在说什么" | 如果概括不出来，说明论点不清晰 |
| 论据支撑充分 | 核心论点有至少2个具体事实/数据支撑 | 删掉论据后，论点是否变成空话 |
| 因果关系成立 | 每个"因为→所以"的推导都合理 | 逐一检查因果句 |
| 无信息矛盾 | 稿子内的数据、事实不自相矛盾 | 检查数字、届别、时间等是否前后一致 |
| 无逻辑跳跃 | 从A到B的推导中间没有缺失环节 | 检查是否有"突然得出结论"的地方 |
| 无过度承诺 | 没有"保证/一定/100%"等绝对化表述 | 搜索绝对化词汇 |
| 条件完整 | 享受福利/适用岗位的条件说清楚了 | 检查是否有"谁能享受""什么条件"的说明 |
| 推荐理由具体 | 推荐的理由是具体的而非空洞的 | "很好"不算理由，"年薪30万+免笔试"才算 |

### 逻辑链完整性检查

根据选题类型，检查对应的逻辑链是否完整（参照 logic_rules.md 第二节）：

```
选题类型：[XX]
逻辑链：
- 环节1（XX）：  ✅完整 / ❌缺失 / ⚠️薄弱
- 环节2（XX）：  ✅完整 / ❌缺失 / ⚠️薄弱
- 环节3（XX）：  ✅完整 / ❌缺失 / ⚠️薄弱
- 环节4（XX）：  ✅完整 / ❌缺失 / ⚠️薄弱
```

### 8种逻辑错误扫描

逐一排查 logic_rules.md 中的8种常见逻辑错误：

| 逻辑错误类型 | 是否存在 | 具体位置（如有） |
| :--- | :--- | :--- |
| 因果倒置 | ✅无 / ❌有 | |
| 以偏概全 | ✅无 / ❌有 | |
| 信息矛盾 | ✅无 / ❌有 | |
| 虚假紧迫 | ✅无 / ❌有 | |
| 空洞推荐 | ✅无 / ❌有 | |
| 逻辑跳跃 | ✅无 / ❌有 | |
| 条件遗漏 | ✅无 / ❌有 | |
| 过度承诺 | ✅无 / ❌有 | |

### 逻辑问题修复策略

| 问题 | 修复方式 |
| :--- | :--- |
| 论点不清晰 | 在钩子之后立即用1句话点明核心信息 |
| 论据不足 | 补充具体数据（薪资、岗位数、截止日期、增长率） |
| 因果不成立 | 重写因果句，确保原因能真正推导出结果 |
| 信息矛盾 | 统一口径，以官方信息为准 |
| 逻辑跳跃 | 在跳跃处补充1-2句过渡推导 |
| 过度承诺 | 将"保证/一定"改为"大大提升/很有机会" |
| 条件遗漏 | 补充适用条件（学历、届别、院校排名等） |

---

## Review 输出格式

每篇稿子 Review 完成后，输出以下格式的 Review 报告：

```
## Review 报告

### 维度一：文案长度
- 目标篇幅：[短版/标准版/长版]
- 实际字数：[X]字
- 口播时长估算：约[X]秒
- 信息密度：每100字[X]个数据点
- 判定：✅达标 / ❌需修改
- 问题（如有）：[具体问题]

### 维度二：文案结构
- 使用模板：模板[X]（[名称]）
- 结构完整性：✅全部环节完整 / ❌缺失[X]个环节
- 留学生锚定：✅有 / ❌缺失
- 互动收尾：✅有 / ❌缺失
- 信息层次：✅有序 / ❌需调整
- 判定：✅达标 / ❌需修改
- 问题（如有）：[具体问题]

### 维度三：文案逻辑
- 核心论点：[一句话概括]
- 逻辑链完整性：✅完整 / ❌[X]个环节缺失或薄弱
- 逻辑错误扫描：✅无错误 / ❌发现[X]个错误
- 判定：✅达标 / ❌需修改
- 问题（如有）：[具体问题]

### 综合判定
- ✅✅✅ 三维度全部达标，可交付
- ❌ [X]个维度需修改，已自动修正，修正后重新 Review
```

**规则**：如果任何一个维度判定为"需修改"，必须先修改再重新 Review，直到三维度全部达标才能交付。
