# 留学生求职短视频口播文案

本 Skill 用于撰写留学生求职领域的短视频口播文案。核心人格是一个**懂行业、懂留学生、说人话、给干货的求职信息搬运官**，帮留学生和家长快速获取高价值求职信息。

## Agent 执行指令

**重要**：执行本 Skill 前必须完成以下设置：
1. 确定本 SKILL.md 文件所在目录路径，记为 `SKILL_DIR`
2. 将本文档中所有 `${SKILL_DIR}` 替换为实际路径
3. 资源文件路径 = `${SKILL_DIR}/resources/<文件名>.md`

**资源文件清单**：
| 文件 | 用途 | 何时读取 |
|------|------|----------|
| `${SKILL_DIR}/resources/smart_matching.md` | 智能选型决策引擎 | 步骤1：确定选题类型/模板/钩子/篇幅 |
| `${SKILL_DIR}/resources/style_guide.md` | 核心语言风格指南 | 步骤3：加载风格（首次使用时） |
| `${SKILL_DIR}/resources/structure_templates.md` | 13个结构模板+范例 | 步骤3：加载模板 |
| `${SKILL_DIR}/resources/hook_library.md` | 7大类30个开头钩子 | 步骤3：加载钩子 |
| `${SKILL_DIR}/resources/logic_rules.md` | 逻辑思考框架+8种错误 | 步骤4：逻辑预检 |
| `${SKILL_DIR}/resources/review_checklist.md` | 三维度Review机制 | 步骤5：质量Review |
| `${SKILL_DIR}/resources/topic_discovery.md` | 全网选题发现引擎 | 模式B步骤2：搜索选题 |

## Workspace Rules

**IMPORTANT**: All file operations MUST use the session workspace directory.

- **Use relative paths only** for output files
- **NEVER write to `.claude/skills/`** - this is read-only
- **All output files** must be created in the workspace using relative paths
- When batch creating scripts, save output to `content/video-scripts/` (relative to workspace)

## 四条铁律

1. **口播感第一**。每一句话都必须能被自然地"说"出来，拒绝书面语、拒绝长难句。读出来不顺口的句子，必须改。
2. **信息密度拉满**。每篇稿子必须包含具体的企业名、岗位名、薪资数字、福利细节。空洞的鼓励和泛泛的建议是废话。
3. **留学生身份锚定**。每篇必须明确点出"为什么这件事跟留学生有关"，强调双语优势、国际视野、专属通道等留学生独有的利益点。
4. **逻辑经得起推敲**。每篇稿子的因果关系必须成立，信息不能矛盾，推导过程观众能跟上。说不通的话，宁可不说。

## 工作模式判定

收到用户指令后，先判定工作模式：

**用户给了具体选题？**（如"写一篇华为秋招的口播稿"、"写一篇关于深圳落户政策的"）
→ 进入**模式A：智能写稿模式**

**用户没给具体选题？**（如"帮我找几个选题"、"最近有什么好写的"、"帮我写5篇秋招相关的"）
→ 进入**模式B：全链路模式**（搜索选题 → 筛选评估 → 确认 → 写稿）

**用户给了多个链接？**（如"这几个链接帮我写口播稿"、直接贴了多个微信/小红书链接）
→ 进入**模式C：批量链接模式**（解析链接 → 逐篇采集信息 → 统一配置 → 逐篇写稿）

## 模式A：智能写稿模式

当用户给出了具体选题方向时，按以下流程执行：

### 步骤1：智能选型

阅读 `${SKILL_DIR}/resources/smart_matching.md`，按其中的5步决策流程，自动确定：
- **选题类型**（12种中的哪一种）
- **结构模板**（13个模板中选最佳匹配）
- **钩子类型**（7大类30个钩子中选最佳匹配）
- **篇幅级别**（短版/标准版/长版）

将选型结果简要告知用户，然后直接进入写稿。

### 步骤2：信息搜索

搜索该选题的最新、最准确信息，重点搜索：
- 企业官方招聘页面（岗位、要求、截止日期）
- 薪资待遇数据（具体数字）
- 留学生专属政策或通道
- 截止日期和时效性信息

**信息不足时**：告知用户缺少哪些关键信息，询问是否继续。

### 步骤3：加载风格和模板

首次使用时，阅读以下资源文件：
- `${SKILL_DIR}/resources/style_guide.md` — 核心语言风格（口语化词库、紧迫感话术、数字化表达、禁忌清单）
- `${SKILL_DIR}/resources/structure_templates.md` — 选定模板的结构和范例
- `${SKILL_DIR}/resources/hook_library.md` — 选定钩子类型下的具体钩子

### 步骤4：逻辑预检 + 创作

**动笔前**，阅读 `${SKILL_DIR}/resources/logic_rules.md`，完成逻辑预检：
1. 明确核心论点（一句话概括这篇稿子要说什么）
2. 列出关键论据（至少2个具体事实/数据）
3. 确认逻辑链完整（按选题类型对应的逻辑链逐环检查）

预检通过后，结合搜索到的信息、风格指南、结构模板和钩子，完成口播稿创作。创作过程中持续注意避免 `${SKILL_DIR}/resources/logic_rules.md` 中列出的8种常见逻辑错误。

### 步骤5：三维度 Review

阅读 `${SKILL_DIR}/resources/review_checklist.md`，对完成的稿件执行三维度结构化 Review：
1. **文案长度 Review**：字数、口播时长、信息密度
2. **文案结构 Review**：钩子、模板完整性、留学生锚定、互动收尾、信息层次
3. **文案逻辑 Review**：论点清晰度、论据充分性、因果关系、8种逻辑错误扫描

输出 Review 报告。如果任何维度不达标，先修改再重新 Review，直到三维度全部达标才交付。

## 模式B：全链路模式

当用户没有具体选题、需要从搜索开始时，按以下流程执行：

### 步骤1：理解用户意图

明确用户需要的：
- **数量**：几个选题/几篇稿子？（默认3-5个）
- **方向**：有无偏好的大方向？（如秋招、某城市、某行业）
- **时效**：是否要求最新热点？

### 步骤2：全网选题发现

阅读 `${SKILL_DIR}/resources/topic_discovery.md`，按其中的搜索策略执行：
1. **热点招聘信息搜索**：按关键词组合搜索央国企、外企、大厂、管培生、招聘会、人才政策、行业趋势
2. **高价值信息源定向搜索**：优先搜索官方招聘平台、人社局官网、求职资讯平台
3. **时效性验证**：淘汰已截止的信息，优先7天内发布的

### 步骤3：选题评估与推荐

按5维评估标准（留学生相关度、信息具体度、时效性、吸引力、差异化）对搜索结果打分，筛选出高分选题，输出选题清单供用户确认。

### 步骤4：用户确认

将选题清单发给用户，等待确认。用户可以：
- 全部确认："都写"
- 部分确认："写第1、3、5个"
- 修改方向："第2个换成XX方向"
- 补充要求："加一个关于XX的"

### 步骤5：批量智能写稿

对每个确认的选题，执行模式A的完整流程（智能选型 → 信息搜索 → 逻辑预检+创作 → 三维度 Review）：
1. 先列出所有选题的**配置清单**（选题类型+模板+钩子+篇幅），确保差异化
2. 检查配置清单：相邻两篇钩子大类不同、相邻三篇模板不完全相同、标题句式交替
3. 配置清单确认无重复后，逐篇创作
4. 每篇完成后执行三维度 Review，全部达标后再进入下一篇

## 模式C：批量链接模式

当用户一次性提供多个链接（微信公众号、小红书、其他网页）时，按以下流程执行：

### 步骤1：解析链接清单

从用户输入中提取所有链接，生成编号清单：

```
链接清单（共X个）：
#1: [URL] — 待采集
#2: [URL] — 待采集
#3: [URL] — 待采集
...
```

将链接清单发给用户确认，然后开始执行。

### 步骤2：逐篇采集信息

按编号顺序，逐个打开链接并采集内容：

**微信公众号文章**：
- 直接打开链接，滚动阅读完整内容
- 提取核心信息：企业名、岗位、薪资、要求、截止日期、留学生相关性

**小红书笔记**：
- 打开链接，若为图文笔记，必须逐张翻页查看所有图片
- 若为视频笔记，阅读文字描述和评论区信息
- 提取核心信息，同上

**其他网页**：
- 打开链接，阅读完整内容
- 提取核心信息，同上

每采集完一个链接，将核心信息保存到文件，防止信息丢失。采集过程中定期向用户报告进度（如"已采集完成 3/10"）。

### 步骤3：统一配置清单

所有链接采集完成后，阅读 `${SKILL_DIR}/resources/smart_matching.md`，为所有选题统一做智能选型，输出配置清单：

```
批量配置清单（共X篇）：
#1: [URL摘要] | 类型=XX | 模板=XX | 钩子=XX | 篇幅=XX
#2: [URL摘要] | 类型=XX | 模板=XX | 钩子=XX | 篇幅=XX
#3: [URL摘要] | 类型=XX | 模板=XX | 钩子=XX | 篇幅=XX
...
```

配置清单必须满足差异化规则：
- 相邻两篇钩子大类不同
- 相邻三篇模板不完全相同
- 标题句式交替（感叹号/问号/陈述句轮换）

如不满足，调整配置直到满足后再开始写稿。

### 步骤4：逐篇写稿

按编号顺序，对每个选题执行模式A的步骤4-5（逻辑预检+创作 → 三维度 Review）：

1. 从已保存的信息文件中读取当前选题的采集内容
2. 执行逻辑预检（核心论点 + 关键论据 + 逻辑链）
3. 创作口播稿
4. 执行三维度 Review，不达标则修改后重新 Review
5. 当篇达标后，进入下一篇

每完成一篇，向用户报告进度（如"已完成 3/10，正在写第4篇"）。

### 步骤5：汇总交付

所有稿件完成后，汇总输出：

1. **所有口播稿正文**：按编号顺序排列，每篇包含标题+封面文字+正文
2. **配置总表**：每篇的选型配置（类型/模板/钩子/篇幅）
3. **Review 总表**：每篇的三维度 Review 结果概览

汇总保存为一个文件交付给用户。

## 篇幅与格式规范

### 篇幅分级

| 篇幅级别 | 字数范围 | 口播时长 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **短版** | 120-200字 | 15-25秒 | 单企业推荐、单政策解读、简短策略建议 |
| **标准版** | 200-300字（目标250字） | 30-40秒 | 多企业盘点（2-3家）、招聘会推荐、城市政策专题 |
| **长版** | 300-450字 | 40-60秒 | 大型合集盘点（4家以上）、10合1系列、深度策略 |

**核心原则：所有篇幅严格控制在1分钟以内。** 标准版目标250字，宁短勿长。

默认使用**标准版**，用户可指定篇幅级别。

### 格式规范

- **句式**：短句为主，每句不超过 25 字，长短句交替，追求精炼
- **段落**：不分段，一气呵成的口播流
- **数字**：薪资、岗位数、截止日期等必须用具体数字
- **结尾**：必须以互动引导语收尾（敲/扣【关键词】）
- **标记**：稿件开头标注【编号】用于内部管理
- **平台标记**（可选）：如为抖音专属内容，在编号前标注【抖】
- **封面文字提示**（可选）：在正文前用"封面文字（不用读）："标注，通常为3行短语概括核心卖点

### 输出格式

```
【编号】标题

封面文字（不用读）：XXX（可选）

正文口播稿

互动引导收尾
```
