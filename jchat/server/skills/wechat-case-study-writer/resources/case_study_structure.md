# 公众号求职案例内容结构分析

本文件定义了创作公众号求职案例文章时，所依赖的 **输入数据结构** 和最终的 **输出文章结构**。

## 一、输入数据结构

原始的求职案例资料，通常包含以下五个部分，顺序固定。这是创作的“原材料”。

### 1. 【背景介绍】
此部分用于快速建立人物画像，提供核心背景信息。
- **学历 (School/Education)**: 候选人的本科和/或硕士院校及专业。
- **Offer**: 拿到的具体录取信息，包括公司、年份、职位。
- **Offer 公司介绍**: 使用 2-3 个标签（Hashtag）简要介绍公司特点。

### 2. 【面试Timeline】
此部分按时间顺序回顾整个面试流程，提供过程性信息。
- **时间线**: 以月份为单位，记录从申请（Apply）到收到录取（Offer）的关键节点。
- **各轮详情**: 简要描述每个环节的内容。

### 3. 【口述记录面经分享】
此部分是文章的核心，详细分享面试中遇到的具体题目。
- **题型分类**: 将题目按类型（如 `Python题`, `SQL题`, `Case题`）进行归类。
- **题目复原**: 尽可能完整地复述题目原文或核心要求。

### 4. 【遇到的挑战】
此部分用于制造「冲突」和「困难」，让故事更具可看性和真实性。
- **候选人短板**: 描述候选人在求职初期面临的客观挑战或能力短板。

### 5. 【解决困难】
此部分作为「挑战」的解答，提供解决方案，完成故事的闭环，突出机构价值。
- **提升策略**: 描述为了克服挑战所采取的具体行动和提升方案。

## 二、输出文章结构 (根据用户反馈更新)

最终生成的公众号文章，应遵循以下结构和格式。

1.  **文章标题**: 简洁直接，有吸引力。 (e.g., `那个华大硕士，是怎样拿下养老大厂Cisco的？`)
2.  **引言**: 场景化引入，机构视角。
3.  **背景信息**: 直接使用 bullet point (•) 列出，**不加小标题**。
    - `•学校背景: ...`
    - `•斩获 Offer: ...`
    - `•“这家公司，我必须得说道说道”: ...`
4.  **`## 这个同学的求职路`**: 将【面试Timeline】故事化、情感化，用 bullet point (•) 按月份呈现。
5.  **`## 面试里到底考了啥`**: 将【口述记录面经分享】干货化，用 `###` 区分题型，用普通括号 `()` 加点评。
6.  **`## 这个同学当时面临的挑战`**: 将【遇到的挑战】转化为故事的低谷。
7.  **`## 我们是怎么帮TA上岸的`**: 将【解决困难】转化为故事的高潮，体现机构价值。
8.  **结尾转化钩子**: **不要鸡汤结尾**。使用 `———` 分隔符，然后加上引流信息。
    - `———`
    - `加我好友: [微信号],  围观更多上岸详细信息`


## 三、长度限制

- **核心要求**: 最终输出的文章，从标题到结尾微信号，总字符数必须控制在 **1000个字符以内**。
- **字符计算**: 无论是中文、英文、数字还是标点符号，都算作1个字符。
